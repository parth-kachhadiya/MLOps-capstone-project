                        +---------------------------+
                        |   AWS EKS Configuration   |
                        +---------------------------+

[1]. Setup
     (a). Installation and version checking
          • Verify AWS CLI : `aws --version`
          • Verify kubectl : `kubectl version --client`
          • Verify eksctl  : `eksctl version` 
            → if eksctl is not recognized as internal or external command, just install it by `choco install eksctl`.
     (b). Create an EKS cluster.
          • `eksctl create cluster  --name mlops-capstone-cluster --region us-east-1 --nodegroup-name mlops-capstone-nodes --node-type t3.small  --nodes 1 --nodes-min 1 --nodes-max 1 --managed`

          ⇨ Above command will hit "CloudFormation" on AWS (check there)
             ⁕ What Is CloudFormation? 
               - AWS CloudFormation is a service that helps define and provision AWS infrastructure as code using templates. It automates the process of creating and managing AWS resources.

             ⁕ How Does It Relate to EKS?
               - When you run eksctl, it generates CloudFormation templates behind the scenes to create:
                 1. The EKS control plane.
                 2. Node groups.
               - CloudFormation ensures that these resources are created and managed as a stack (a logical grouping of resources).

             ⁕ What Is a Stack in CloudFormation?
               - A CloudFormation Stack is a collection of AWS resources (like VPCs, subnets, EC2 instances, etc.) managed as a single unit. For EKS:
                 1. eksctl-flask-app-cluster-cluster stack : (Creates the EKS control plane).
                 2. eksctl-flask-app-cluster-nodegroup-flask-app-nodes stack : (Creates the worker nodes).

               - Each stack contains:
                 1. A template defining the resources (YAML or JSON).
                 2. Resource dependencies and configurations.

     (c). Update the kubectl config (Once the cluster is created, eksctl will automatically update your kubectl config file. however you can verify and set it manually using below command).
          • OPTIONAL : `aws eks --region us-east-1 update-kubeconfig --name mlops-capstone-cluster` (This ensures that your kubectl is pointing to the correct cluster.)
     (d). Check your EKS cluster configurations, ensure that you can access your EKS cluster by executing below command.
          • `aws eks list-clusters`
     (e). Verify cluster status.
          • `aws eks --region us-east-1 describe-cluster --name mlops-capstone-cluster --query "cluster.status"` (Optionally, verify from UI)
     (f). Check cluster connectivity.
          • `kubectl get nodes`
     (g). Check the namespaces.
          • `kubectl get namespaces`
     (h). Verify the deployment.
          • `kubectl get pods`
          • `kubectl get svc`
     (i). Edit enbound rules.
          

     (HELPER). Delete cluster
          • Format : eksctl delete cluster --name <CLUSTER_NAME> --region <REGION>
          • `eksctl delete cluster --name mlops-capstone-cluster --region us-east-1`
          • `eksctl get cluster --region us-east-1` (Verify cluster deletion)

[2]. Deploy the app on EKS via CICD pipeline, also edit the security group for nodes and edit inbound rule for 5000 port.
     • Edit 'CI.yaml' and 'Dockerfile'.
     • Add 'deployment.yaml'.
     • Click on EC2 cluster id (created by kubectl) > Security > Security groups > Edit enbound rules > 
       Add rule : [Type : Custom TCP, Port range : 5000, Source : Anywhere-IPv4] > Save rules. 
     • Git add > commit > push.

[3]. Get Load balancer URL / external-ip
     • `kubectl get svc flask-app-service`

[4]. Try `<external-ip>:5000`
     • afbb28255a1eb4a048665e974a3ae01e-329529135.us-east-1.elb.amazonaws.com:5000
     • Test : `curl afbb28255a1eb4a048665e974a3ae01e-329529135.us-east-1.elb.amazonaws.com:5000` on cmd

                        +-----------------------------+
                        |   Prometheus server setup   |
                        +-----------------------------+

[1]. Namespace check.
     • `kubectl get namespaces`

[2]. EC2 for Prometheus
     • Launch an EC2 instance with configurations.
       - OS : Obuntu
       - Instance type : t3.medium
       - Check [Allow SSC traffic from anywhere, Allow HTTPS traffic from the internet, Allow HTTP traffic from the internet]
       - Configure storage : 20
       -> Launch instance
      🚨 Security (Prometheus server ec2) > Security groups > Edit inbound rules > Add rule >
         Add rule : [Type : Custom TCP, Port range : 9090, Source : Anywhere-IPv4] > Save rules. 

     (HELPER). If you want to access ec2 on your system
     ⇨ `ssh -i <your_key.pem> ubuntu@<your-ec2-public-ip>` (Make sure that your .pem file is in your current folder where your cmd/powershell is running)

[3]. Execute below commands one by one on EC2 console.
     • sudo apt update && sudo apt upgrade -y
     • `wget https://github.com/prometheus/prometheus/releases/download/v3.10.0/prometheus-3.10.0.linux-amd64.tar.gz`  (Install prometheus)
     • `tar -xvzf prometheus-3.10.0.linux-amd64.tar.gz` (Extract the downloaded archieve)
     • `mv prometheus-3.10.0.linux-amd64 prometheus`

[4]. Move files to standard path.
     • `sudo mv prometheus /etc/prometheus`
     • `sudo mv /etc/prometheus/prometheus /usr/local/bin/`

[5]. Create prometheus configurations.
     • `sudo nano /etc/prometheus/prometheus.yml`  (Open file for editing)
       ```
       global:
         scrape_interval: 10s
       
       scrape_configs:
         - job_name: "flask-app"
           static_configs:
             - targets: ["afbb28255a1eb4a048665e974a3ae01e-329529135.us-east-1.elb.amazonaws.com:5000"]
       ```
       Press : Ctrl + o > Enter > Ctrl + x 
     • `cat /etc/prometheus/prometheus.yml` (Verify changes)
     • `which prometheus` (Returns full prometheus binary path)

[6]. Run prometheus with config file.
     • `<output_of_which_prometheus_command> --config.file=/etc/prometheus/prometheus.yml`
       `/usr/local/bin/prometheus --config.file=/etc/prometheus/prometheus.yml`
     • To open prometheus server:
       - Copy IPv4 address of prometheus-server ec2 instance.
